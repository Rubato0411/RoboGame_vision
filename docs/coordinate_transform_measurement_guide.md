# RoboGame 视觉坐标变换参数测量指南

## 1. 文档目的

坐标变换模块需要把以下信息连接起来：

```text
图像像素 → 相机坐标 → 机器人坐标 → 场地坐标
```

需要获得三组真实参数：

1. 相机内参：由棋盘格标定得到，不使用卷尺手工测量。
2. 相机外参：相机相对机器人坐标系的位置和方向。
3. 场地标签地图：6 个 AprilTag 在场地坐标系中的位置和方向。

如果需要把方块像素位置投影到地面或平台，还必须测量工作平面的高度。

本项目统一使用米和角度：

- 距离单位：m
- 配置文件角度单位：deg
- 角度顺序：Roll、Pitch、Yaw
- `T_A_B`：把 B 坐标系中的点转换到 A 坐标系

---

## 2. 建议准备的工具

- 5 m 或更长的钢卷尺
- 150 mm 以上游标卡尺
- 直角尺
- 激光测距仪（推荐但不是必须）
- 数字倾角仪或带倾角功能的手机
- 激光水平仪或水平尺
- 细线、铅垂线和美纹纸胶带
- 记号笔
- 打印好的 15 cm AprilTag
- 相机标定棋盘格
- 用于记录数据的表格

卷尺适合场地尺寸；卡尺适合相机安装偏移和标签实际边长。不要只依赖手机测距应用。

---

## 3. 先固定所有坐标轴定义

坐标轴一旦确定，后续测量、控制和通信都不能随意更改。

### 3.1 场地坐标系 `field`

推荐使用右手坐标系：

- 原点：己方半场一个永久、容易复测的地面角点
- `X_field`：沿场地长边向前
- `Y_field`：从己方视角向左
- `Z_field`：竖直向上

必须在场地图上标出原点和 X、Y 正方向，并让控制组共同确认。

### 3.2 机器人坐标系 `robot`

推荐使用右手坐标系：

- 原点：机器人底盘旋转中心在地面的投影点
- `X_robot`：机器人正前方
- `Y_robot`：机器人左方
- `Z_robot`：机器人上方

如果控制组已经使用其他定义，以控制组定义为准，但必须同步修改视觉文档和配置。

### 3.3 OpenCV 相机坐标系 `camera`

OpenCV 默认相机坐标轴为：

- 原点：相机光心
- `X_camera`：图像右方
- `Y_camera`：图像下方
- `Z_camera`：镜头朝向的前方

因此，相机水平朝向机器人前方时，`camera` 与 `robot` 的坐标轴仍然不重合。不能因为相机“正装”就填写：

```json
"rpy_deg": [0, 0, 0]
```

以本文推荐的机器人坐标轴为例，水平前视相机大致满足：

```text
Z_camera → X_robot
X_camera → -Y_robot
Y_camera → -Z_robot
```

理想安装的一个参考角度约为 `[-90°, 0°, -90°]`，但真实参数必须根据实际支架方向校验，不能直接照抄。

### 3.4 AprilTag 坐标系 `tag`

本项目中标签坐标轴定义为：

- 原点：标签有效外边框中心
- `X_tag`：沿标签印刷面的右方
- `Y_tag`：沿标签印刷面的上方
- `Z_tag`：垂直标签平面、朝标签正面外侧

测量时必须记录标签是否旋转、倒置，以及安装在哪一面墙上。

---

## 4. 相机内参需要获得什么

相机内参由棋盘格程序输出：

- 焦距 `fx`、`fy`
- 主点 `cx`、`cy`
- 畸变系数
- 标定图像宽度和高度
- 重投影误差

内参标定时需要人工准确测量：

- 棋盘格内角点列数
- 棋盘格内角点行数
- 单个方格的实际边长
- 正式运行分辨率

以下设置必须在标定后保持不变：

- 摄像头和镜头
- 分辨率
- 对焦位置
- 数字变焦和裁切模式

建议使用同一张平整棋盘格采集 30～50 张不同距离和角度的照片。

---

## 5. 测量相机相对机器人的外参

配置项为：

```text
T_robot_camera
```

它表示把相机坐标转换到机器人坐标。

### 5.1 需要测量的平移量

需要测量相机光心在机器人坐标系中的位置：

```text
tx：相机光心相对机器人原点的前后距离
ty：相机光心相对机器人原点的左右距离
tz：相机光心离机器人坐标原点平面的高度
```

填写方式：

```json
"translation_m": [tx, ty, tz]
```

符号示例：

- 相机在机器人原点前方：`tx > 0`
- 相机在机器人原点左侧：`ty > 0`
- 相机在机器人原点上方：`tz > 0`

相机光心通常近似位于镜头内部，不是保护壳前表面。可查相机机械图；没有机械图时，可以用镜头前端附近作为初值，再通过外参校正实验优化。

### 5.2 需要测量的旋转量

需要确定相机坐标轴在机器人坐标系中的方向：

- Roll：绕 X 轴旋转
- Pitch：绕 Y 轴旋转
- Yaw：绕 Z 轴旋转

本项目使用：

```text
R = Rz(Yaw) × Ry(Pitch) × Rx(Roll)
```

仅使用倾角仪通常只能比较准确地得到俯仰和横滚，偏航角还需要相对机器人中心线测量。

推荐步骤：

1. 在底盘上标出机器人 X 轴中心线。
2. 测量镜头光轴相对中心线的水平夹角。
3. 测量光轴向上或向下的倾角。
4. 检查图像水平线是否倾斜，估计相机横滚。
5. 使用已知位置 AprilTag 对测量值进行优化验证。

手工测量值适合作为初值。需要精确抓取时，建议最终通过 PnP 或手眼标定优化外参。

### 5.3 每个相机分别测量

如果机器人有前视相机和夹爪相机，每台相机都需要独立的：

- 内参文件
- `T_robot_camera`
- 安装位置
- 安装方向
- 正式分辨率

不要把一台相机的参数用于另一台相机。

## 6. 测量 6 个 AprilTag 的场地位姿

每个标签都需要完整的：

```text
T_field_tag
```

不仅要测标签中心坐标，还要测标签正面朝向。

### 6.1 标签中心位置

对 ID 1～6 分别测量：

- `x`：标签中心到场地 YZ 原点平面的距离
- `y`：标签中心到场地 XZ 原点平面的距离
- `z`：标签中心离地高度

规则给出标签：

- 正方形边长 15 cm
- 上边缘高度 40 cm

如果标签竖直、实际有效外边框确实为 15 cm，则标签中心高度初值为：

```text
z = 0.40 - 0.15 / 2 = 0.325 m
```

仍需现场测量确认：

- 15 cm 是标签有效黑色外框还是包含白色打印边距
- 墙体、地面和标签是否真正水平/竖直
- 上边缘高度是否存在施工误差

坐标应以标签有效检测外边框中心为准，不是整张打印纸中心。

### 6.2 标签朝向

需要记录：

- 标签安装在哪面墙
- 标签正面法向指向场地哪个方向
- 标签印刷上边缘是否水平
- 标签是否旋转 90°、180°或倒置

最稳妥的记录方式是测量三个点在场地中的位置：

```text
C：标签中心
R：从中心沿标签右方向的参考点
U：从中心沿标签上方向的参考点
```

由此得到：

```text
X_tag = normalize(R - C)
Y_tag = normalize(U - C)
Z_tag = normalize(X_tag × Y_tag)
```

旋转矩阵由三列组成：

```text
R_field_tag = [X_tag  Y_tag  Z_tag]
```

再转换成配置文件使用的 RPY。相比只写“在左墙”或“朝南”，三点法更不容易出现正负号错误。

## 7. 测量地面和平台平面

单目相机把方块像素转换为三维位置时，需要假设方块位于已知平面。

需要测量：

- 主地面高度
- 高台顶部高度
- 斜坡起点、终点和倾角
- 方块中心相对支撑面的高度
- 夹爪抓取基准面的高度

若场地坐标系 `Z=0` 定义在主地面，则主地面为：

```text
法向量 n = [0, 0, 1]
平面偏移 offset = 0
```

高度为 `h` 的水平平台满足：

```text
Z = h
n · X - h = 0
plane_offset = -h
```

方块检测框中心不一定对应方块与地面的接触点。定位抓取点时需要根据相机视角选择底边中心、方块中心或通过已知尺寸估计三维姿态。

## 8. 参数填写方法

复制模板：

```text
configs/coordinate_frames.example.json
```

生成正式文件：

```text
configs/coordinate_frames.json
```

相机参数示例结构：

```json
"robot_from_camera": {
  "configured": true,
  "translation_m": [0.18, 0.00, 0.42],
  "rpy_deg": [-90.0, 0.0, -90.0]
}
```

上述数字仅用于展示格式，不是机器人真实参数。

标签参数示例结构：

```json
"1": {
  "configured": true,
  "translation_m": [测得X, 测得Y, 测得Z],
  "rpy_deg": [测得Roll, 测得Pitch, 测得Yaw]
}
```

未实测的条目必须保留：

```json
"configured": false
```

不要用全零参数假装已经标定。

## 9. 参数验收方法

### 9.1 单标签静态检查

把机器人放在场地内 5～10 个已知位置：

1. 人工测量机器人中心的真实 X、Y 和朝向。
2. 使用 AprilTag 计算机器人位姿。
3. 比较视觉值与人工测量值。
4. 分别从不同标签、不同距离和不同角度测试。

### 9.2 多标签一致性检查

机器人保持静止，同时看到两个标签时，分别计算两次机器人位置。

如果两个结果差异很大，常见原因是：

- 某个标签坐标填错
- 标签法向方向写反
- 标签旋转角度错误
- 相机外参方向写反
- `T_A_B` 与 `T_B_A` 混淆
- 标签实体尺寸填写错误

### 9.3 建议初期验收目标

- 静态场地定位位置误差：不超过 30～50 mm
- 静态偏航角误差：不超过 2～3°
- 多标签位置结果差：不超过 50 mm
- 同一点重复测量标准差：不超过 10～20 mm
- AprilTag 重投影误差：尽量低于 1 px

最终标准要根据机器人抓取容差、场地尺寸和控制系统要求确定。

## 10. 到货后的推荐执行顺序

1. 确定场地坐标原点和正方向。
2. 确定机器人坐标原点和正方向。
3. 固定相机分辨率、曝光、白平衡和焦距。
4. 使用棋盘格完成相机内参标定。
5. 固定相机支架，测量相机平移和安装角度。
6. 测量 6 个标签的中心坐标和朝向。
7. 测量地面、平台和抓取平面的高度。
8. 填写 `coordinate_frames.json`。
9. 做单标签静态验证。
10. 做多标签一致性验证。
11. 优化相机外参。
12. 将坐标结果接入连续帧跟踪和下位机通信。

只要相机支架位置、镜头焦距、图像裁切或标签位置发生变化，都必须重新验证相关参数。

### 倒置成像与 AprilTag 位姿

场地文件中的 `field_from_tags` 始终记录标签的真实物理位姿，不得用标签
RPY补偿摄像头倒置。当前前视CSI摄像头输出倒置画面时，在
`configs/apriltag_detector.json` 中设置：

```json
"pose_image_rotation_deg": 180
```

检测器保持原始像素、内参和检测框不变，仅在 `solvePnP` 前将角点从
`[0, 1, 2, 3]` 重排为 `[2, 3, 0, 1]`。摄像头恢复正立成像后必须改回
`0`。禁止同时修改标签RPY补偿，否则会形成两次180度修正。
