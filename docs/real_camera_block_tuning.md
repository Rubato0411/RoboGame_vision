# 真实摄像头方块检测调参指南

## 原则

先稳定相机成像，再调整检测器。自动曝光、自动白平衡和自动对焦持续变化时，任何HSV阈值都难以稳定。

推荐顺序：

```text
相机模式 → 曝光/增益 → 白平衡 → 焦距 → ROI → HSV → 形态学 → 面积 → 几何 → 压力测试
```

## 1. 固定摄像头工作模式

先运行图像查看器：

```powershell
python run_viewer.py --source 0 --backend dshow --fourcc MJPG --width 1280 --height 720 --fps 30
```

按`P`检查实际参数。实际分辨率、FPS或FOURCC与请求值不同时，先解决视频模式问题，不要开始颜色调参。

前视和夹爪相机应分别保存配置。两台相机即使型号相同，曝光和白平衡也可能不同。

## 2. 固定成像参数

在接近正式比赛的灯光下依次处理：

1. 关闭自动对焦，调整到工作距离内方块边缘最清楚。
2. 关闭自动曝光，缩短曝光直到机器人运动时边缘不明显拖影。
3. 增加增益补偿亮度，但避免明显彩色噪声。
4. 关闭自动白平衡，固定色温，使橙色和紫色在多帧间不漂移。
5. 保持相机、镜头、分辨率和安装位置不再变化。

曝光优先级：

```text
无运动模糊 > 不过曝 > 噪声较低 > 画面看起来明亮
```

人眼觉得偏暗但颜色稳定的图像，通常比明亮却拖影的图像更适合检测。

## 3. 采集调参数据集

不要只对着一帧调参数。每台相机至少采集以下内容：

```text
normal/       正常距离和角度
near/         近距离、大目标
far/          最远工作距离
shadow/       阴影和暗面
bright/       高光和较亮区域
motion/       机器人移动时
occluded/     被夹爪或其他方块遮挡
multiple/     多个方块相邻
negative/     没有方块、但存在相近颜色物体
```

每类建议20～50帧。必须保留原始图片或原始视频，不要只保存带框结果。

## 4. 设置ROI

增强版配置使用归一化ROI：

```json
"roi_normalized": [0.0, 0.2, 1.0, 1.0]
```

顺序为：

```text
[左边界, 上边界, 右边界, 下边界]
```

每个值在0～1之间。上例忽略画面顶部20%。

ROI应排除：

- 机器人自身橙色或紫色零件；
- 永远不可能出现方块的天空、墙顶或车体区域；
- 固定电线、保护罩和夹爪结构。

ROI不能切掉最远、最近和抓取过程中的合法方块。

## 5. 调整HSV

启动交互工具：

```powershell
python tools\tune_block_detector.py --source "D:\data\test.mp4" --loop
```

视频按文件记录的FPS播放。工具启动时会打印FPS、总帧数和时长；少于3帧的
损坏或错误封装视频会被拒绝。快捷键：

- `Space`：暂停/继续；
- `A` / `D`：上一帧/下一帧；
- `J`：向后跳转30帧；
- `L`：向前跳转30帧；
- `C`：切换橙色/紫色；
- `W`：保存；
- `R`：重新加载已保存配置；
- `Q`：退出。

调整滑块前先暂停视频，随后逐帧检查正常、阴影、运动、遮挡和负样本。

调节顺序：

1. 将S、V下限暂时调低，先确定H范围。
2. 缩小H范围，直到大部分相近颜色背景被排除。
3. 提高S下限，排除灰色场地和白色反光。
4. 提高V下限，排除黑线和极暗噪声。
5. 检查阴影、远距离和运动视频是否仍能完整保留方块。

理想掩码不是绝对完美的白色矩形，而是：目标主体连续、背景误检少、不同场景下稳定。

## 6. Gamma和CLAHE

配置：

```json
"gamma": 1.0,
"clahe_enabled": false
```

默认先保持关闭。只有固定曝光后仍存在明显暗区时再试。

- `gamma > 1`：当前实现会提亮暗部；
- `gamma < 1`：压暗画面；
- CLAHE：改善局部明暗差，但也可能放大噪声和改变颜色边界。

每次只启用一种补偿，并重新检查HSV分布。不要同时自动曝光、Gamma和CLAHE一起调。

## 7. 形态学参数

```json
"morph_kernel": 5,
"open_iterations": 1,
"close_iterations": 2
```

- 开运算去除小噪点；
- 闭运算填补高光、泡棉纹理造成的孔洞；
- 核越大、次数越多，越容易把相邻方块粘在一起。

先用3或5的核。只有噪点尺寸明显更大时才使用7以上。

## 8. 面积阈值必须按分辨率和相机角色分别设置

```json
"min_area_px": 500
```

统计最远合法方块的最小轮廓面积，以及误检噪声的最大面积：

```text
最大噪声面积 < min_area_px < 最远合法方块面积
```

前视相机看到的远处方块小，`min_area_px`应较低；夹爪相机工作距离固定，阈值可以更高。

更改分辨率后，像素面积近似按宽高缩放比例的乘积变化，必须重新调整。

## 9. 几何过滤

增强版同时计算：

- 轴对齐矩形度`rectangularity`；
- 旋转矩形度`rotated_rectangularity`；
- 凸实度`solidity`；
- 颜色覆盖率`color_coverage`；
- 旋转框角度；
- 是否触碰ROI边界。

真实倾斜方块的轴对齐矩形度可能较低，因此不要把`min_rectangularity`设得过高。主要依靠旋转矩形度和凸实度排除不规则区域。

建议初始范围：

```text
min_rectangularity          0.30～0.50
min_rotated_rectangularity  0.55～0.80
min_solidity                0.70～0.90
min_color_coverage          0.30～0.60
```

遮挡越严重，需要越低的矩形度、凸实度和覆盖率；阈值降低后必须通过ROI和颜色范围控制误检。

## 10. 边界目标策略

```json
"reject_border_touching": false
```

搜索阶段建议为`false`，保留刚进入视野的方块，但其置信度会受到轻微惩罚。

抓取精对准阶段可设为`true`：目标必须完整进入ROI后才允许输出对准结果。更好的长期方案是检测器保留目标，由视觉伺服模块根据`touches_border`决定是否允许抓取。

## 11. 根据拒绝统计定位问题

演示画面会显示`rejected`统计：

```text
area_too_small       面积阈值过高或目标太远
aspect_ratio         形状太细长或方块掩码破碎
rectangularity       轴对齐矩形度不足
rotated_rectangularity 旋转矩形度不足
solidity             遮挡、孔洞或不规则轮廓
color_coverage       HSV掩码不完整
touches_border       目标碰到ROI边界
```

调参时先看掩码，再看拒绝原因。掩码错误应调整成像和HSV；掩码正确但没有框，才调整几何参数。

## 12. 分别建立前视与夹爪配置

建议最终保存：

```text
configs/block_detector_front.json
configs/block_detector_gripper.json
```

前视相机侧重：低最小面积、容忍透视、允许边界目标。

夹爪相机侧重：较小ROI、较高最小面积、较严格颜色覆盖率、稳定的近距离曝光。

## 13. 验收方法

在固定测试集上记录：

```text
TP：正确检测的方块
FP：不存在方块却输出检测
FN：存在方块但漏检
```

至少计算：

```text
精确率 = TP / (TP + FP)
召回率 = TP / (TP + FN)
```

抓取前精对准更重视精确率；远距离搜索更重视召回率。不要用一组阈值同时承担两个阶段的全部需求。

## 14. 推荐实机调试流程

1. 相机固定后录制5～10分钟原始视频。
2. 离线调出第一组参数。
3. 在未参与调参的另一段视频上验证。
4. 找出所有误检和漏检帧，按原因分类。
5. 每次只修改一类参数。
6. 重新跑完整测试集，而不是只看刚才失败的一帧。
7. 参数冻结后进行运动、阴影、相邻方块和遮挡压力测试。
8. 保存配置、相机参数、标定文件和对应测试结果。
