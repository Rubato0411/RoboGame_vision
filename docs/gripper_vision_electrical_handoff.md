# 夹爪视觉模块向电控交付与联合验收指南

## 1. 当前交付结论

截至提交 `104f75b`，夹爪视觉已经完成：

- `camera0` 与夹爪相机角色确认；
- IMX708 夹爪相机内参测量，45 张有效图，平均重投影误差约 `0.151 px`；
- 固定曝光、增益、白平衡增益和镜头位置登记；
- 橙色、紫色方块二维检测调参；
- 夹爪参考像素 `[766.43, 261.43]`；
- 倒置画面的二维误差方向修正；
- 二维中心容差 `±12 px`、角度容差 `±5°`；
- 二维对准模块验收。

可以向电控交付的范围是：

```text
方块颜色、目标ID、置信度、二维中心误差dx/dy、图像角度误差、aligned状态
```

目前不能宣称已经交付：

```text
机器人坐标系三维抓取点、完整手眼标定、机械臂闭环抓取、抓取成功率
```

机器可读的交付状态见 `configs/gripper_electrical_handoff.json`。

## 3. 二维对准接口

`VisionOutput.gripper_alignment`：

```json
{
  "valid": true,
  "target_track_id": 12,
  "dx_px": 8.0,
  "dy_px": -5.0,
  "angle_error_deg": 2.0,
  "aligned": true,
  "confidence": 0.91,
  "predicted": false,
  "reason": "ok"
}
```

当前倒置补偿后的定义：

| 字段 | 含义 |
|---|---|
| `dx_px > 0` | 目标位于转正后画面的参考点右侧 |
| `dx_px < 0` | 目标位于参考点左侧 |
| `dy_px > 0` | 目标位于参考点下方 |
| `dy_px < 0` | 目标位于参考点上方 |
| `angle_error_deg` | 方块角度相对期望角度的最短误差，按90°对称处理 |
| `aligned=true` | 置信度、位置和角度同时进入配置容差 |

电控不得把像素正负号直接等同于某个机械臂关节正负方向。相机安装方向、机械臂构型和
当前末端姿态都会影响映射，必须通过低速小步运动共同确认。

## 4. 二维对准联合验收

机械臂先保持在安全高度，不闭合夹爪：

1. 视觉持续输出同一 `target_track_id`；
2. 电控使末端沿候选正方向移动一个很小距离；
3. 双方观察 `abs(dx_px)` 或 `abs(dy_px)` 是减小还是增大；
4. 若增大，电控反转该控制轴映射；
5. 分别验证 X、Y 和角度；
6. 只在误差连续多帧进入容差时接受 `aligned`；
7. `valid=false`、`predicted=true`、目标ID变化或超时立即停止视觉伺服；
8. 保存每次移动前后像素误差和机械臂位姿。

二维对准通过只证明“图像中心误差能收敛”，不证明夹爪在三维空间到达正确抓取点。

## 5. 为什么手眼标定必须由电控协助

如果夹爪相机刚性安装在机械臂末端并随机械臂运动，它属于眼在手上
（eye-in-hand）。需要求：

```text
T_tool_camera：相机坐标到末端工具坐标的固定变换
```

运行时机器人坐标中的相机位姿为：

```text
T_robot_camera(t) = T_robot_tool(t) × T_tool_camera
```

其中 `T_robot_tool(t)` 每个时刻都随机械臂变化，只能由STM32/机械臂控制器根据关节、
编码器和运动学提供。视觉组单独拍图无法得到这部分数据。

现有 `CoordinateTransformer` 使用静态 `robot_from_camera`。这只适用于相机固定在车体的
情况。如果夹爪相机随末端移动，在接入实时 `T_robot_tool(t)` 前，禁止把静态
`coordinate_geometry_file` 作为正式三维抓取外参。

### 电控必须提供

- 机器人基座坐标系和工具坐标系定义；
- 长度单位和角度单位；
- 每张标定图对应的 `T_robot_tool` 或等价齐次矩阵；
- 图像帧与机械臂位姿的公共 `sample_id` 和时间戳；
- 机械臂到位并稳定的确认信号；
- 低速点动能力、软限位、碰撞保护和急停；
- 末端重复定位精度测试结果；
- 如果STM32不做正运动学，由电控提供关节角及权威运动学计算端。

### 视觉组必须提供

- 夹爪相机原始内参文件；
- 每张样本中的标定板相对相机位姿；
- 手眼求解、残差和异常样本剔除；
- `T_tool_camera` 及其坐标约定；
- 独立验证集上的平移、旋转误差；
- 运行时三维结果的有效性和置信度。

## 6. 手眼标定采集操作

假设标定板固定在机器人基座/场地中，夹爪相机随末端运动：

1. 固定标定板，整个采集期间不得移动；
2. 锁定夹爪相机曝光、白平衡、焦距和分辨率；
3. 电控将机械臂移动到不少于 15 个姿态，推荐 20～30 个；
4. 姿态应覆盖不同位置以及绕多个轴的旋转，不能全部只有平移或绕单轴旋转；
5. 每个姿态到位后等待机械振动停止；
6. 电控生成唯一 `sample_id`，记录时间戳和 `T_robot_tool`；
7. 视觉用相同 `sample_id` 保存原图和标定板检测结果；
8. 不允许用“第N张图大概对应第N个位姿”的人工猜测配对；
9. 至少留出 5 个未参与求解的姿态做验证；
10. 求解后重新采集一组独立数据检查平移和旋转残差。

建议每条样本保存：

```json
{
  "sample_id": 17,
  "image_timestamp_s": 1234.567,
  "controller_timestamp_s": 1234.565,
  "settled": true,
  "T_robot_tool": {
    "translation_m": [0.31, -0.12, 0.42],
    "rpy_deg": [175.0, 4.0, -86.0]
  },
  "image_file": "hand_eye/sample_017.png"
}
```

双方必须先确认变换方向。本文统一使用 `T_A_B` 表示“将B坐标转换到A坐标”。

## 7. 三维抓取坐标联合验收

三维输出为：

```text
blocks[].position_robot_m
blocks[].grasp_point_robot_m
```

在完成手眼标定、实时末端位姿接入、支撑面高度确认之前，这两个字段必须为 `null` 或
`valid=false`，不得向机械臂发送全零假坐标。

### 第一阶段：已知点静态误差，不闭合夹爪

1. 在工作平面布置至少 9 个已测量点，覆盖中心、四角和边缘；
2. 方块分别放在每个点，记录真实中心和顶部抓取点；
3. 机械臂从至少 3 个不同观察姿态采集；
4. 比较 `grasp_point_robot_m` 与真值；
5. 分别统计 X/Y/Z 平均误差、P95误差和最大误差；
6. 检查单位、轴向和符号；
7. 任何点出现固定轴交换或符号错误，立即停止机械臂联调。

### 第二阶段：悬停验证

1. 机械臂先移动到抓取点上方安全距离，例如 50～100 mm；
2. 视觉和电控共同确认XY误差；
3. 使用限速、小步下降，不闭合夹爪；
4. 测量夹爪中心与方块中心的实际偏差；
5. 验证不同机械臂姿态下误差没有明显变化；
6. 完成碰撞边界和工作空间检查。

### 第三阶段：低速真实抓取

只有前两阶段通过后才能闭合夹爪：

1. 设置最大速度、加速度和夹持力；
2. 电控提供闭合、接触/压力和故障反馈；
3. 视觉确认目标随夹爪抬起，不能只用“方块消失”判断成功；
4. 重复测试近、中、远和不同角度；
5. 统计抓取成功率、首次成功率和失败原因；
6. 验证丢帧、目标丢失、坐标超时和急停。

最终容差必须根据夹爪开口、方块10 cm尺寸和机械误差共同确定，不能由视觉组单方面给出。

## 8. STM32/机械臂反馈要求

至少需要提供：

```json
{
  "lower_controller_healthy": true,
  "fault_detected": false,
  "grasp_confirmed": false,
  "place_pose_reached": false,
  "release_confirmed": false
}
```

联合三维功能还需要新增或通过另一条权威状态通道提供：

```text
sample_id
controller_timestamp_s
T_robot_tool 或关节角
motion_settled
gripper_open/gripper_closed
contact_detected/pressure_value
arm_fault/limit_active
```

当前 `RobotFeedback` 尚未包含实时 `T_robot_tool`。这是眼在手上三维抓取接入前必须由
双方扩展的数据合同，不能用低频、无时间戳的普通状态量代替。
