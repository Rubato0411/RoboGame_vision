# 方块检测视频调参与基线评估指南

## 1. 为什么要建立固定基线

直接拖动 HSV 滑块并观察一张图片，容易出现以下问题：

- 当前画面效果变好，其他光照下变差。
- 为了找回一个漏检方块，引入大量误检。
- 调参前后没有统一评价标准。
- 反复使用同一批画面，参数只适合这些画面。

基线的核心是：固定一组人工确认过的画面，在相同画面上比较每版配置的误检和漏检。

本项目建议先做“小型计数基线”，熟悉流程后再升级到逐方块框标注。

---

## 2. 第一步：从视频抽取代表帧

在 VS Code 中打开终端：

```powershell
conda activate D:\conda_envs\rg_vision
cd D:\RoboGameVision
```

每 0.5 秒抽取一帧：

```powershell
python tools\extract_video_frames.py `
  --source "data\test_video.mp4" `
  --output-dir "data\block_baseline" `
  --interval 0.5
```

18 秒视频大约得到 37 张图片，并生成：

```text
data/block_baseline/annotations.csv
```

如果运动较快，可把间隔改为 0.25 秒；如果相邻画面非常相似，可改为 0.75 或 1 秒。

不要简单保留大量相邻帧。应保证样本覆盖：

- 近、中、远距离方块
- 画面中心和四周边缘
- 正视和明显倾斜
- 单个方块和连接方块
- 橙色和紫色
- 暗区、亮区、阴影、反光
- 静止画面和运动模糊
- 方块部分遮挡
- 场地内容易误检的装饰、墙体和机器人零件
- 没有方块的纯负样本

建议第一版保留 30～50 张有差异的代表帧。

---

## 3. 第二步：划分调参集与验证集

把抽出的图片分为：

- `tune`：约 70%，用于观察和调整参数。
- `validation`：约 30%，只用于最终比较，不参与日常调参。

在 `annotations.csv` 的 `split` 列填写：

```text
tune
validation
```

推荐 40 张图片的划分：

```text
28 张 tune
12 张 validation
```

两个集合都必须包含近远距离、不同光照、连接方块和无方块场景。不要把容易画面全部放进调参集、困难画面全部放进验证集。

---

## 4. 第三步：人工标记真实数量

逐张打开图片，填写：

- `orange_gt`：实际可见橙色方块数量
- `purple_gt`：实际可见紫色方块数量
- `scene_notes`：场景说明

示例：

```csv
image,orange_gt,purple_gt,scene_notes
frame_000120.jpg,3,0,三个橙色方块，右侧两个相连
frame_000240.jpg,1,1,远距离，有运动模糊
frame_000360.jpg,0,0,纯负样本，墙面有红白装饰
```

标注规则必须提前统一：

1. 只露出极小部分、无法用于抓取的方块是否计数。
2. 被遮挡超过多少比例不计数。
3. 画面边缘被裁掉的方块是否计数。
4. 连接方块按物理方块数量计数，而不是按连接区域计数。

推荐规则：能明确辨认出独立方块主体且可见面积超过约 50% 才计入有效目标。比赛控制有不同要求时，以控制需求为准。

只有数量标注可能出现“一个漏检加一个误检，预测总数刚好正确”的情况。因此数量只是第一轮快速基线，最终仍需逐框核对 TP、FP、FN。

---

## 5. TP、FP、FN 的含义

对每种颜色分别统计：

- TP（正确检测）：检测框确实对应一个真实方块。
- FP（误检）：检测框对应墙面、装饰、机器人零件等非方块。
- FN（漏检）：真实方块没有对应检测框。

同一检测框不能匹配两个真实方块；同一真实方块也不能同时匹配两个检测框。

连接的三个物理方块如果只输出一个大框：

```text
TP = 1
FN = 2
```

一个真实方块被错误拆成三个框：

```text
TP = 1
FP = 2
```

填写 `annotations.csv` 中：

```text
orange_tp orange_fp orange_fn
purple_tp purple_fp purple_fn
```

---

## 6. 评价指标

每种颜色分别计算：

```text
Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
F1        = 2 × Precision × Recall / (Precision + Recall)
```

含义：

- Precision 高：程序报出的目标大多是真的，误检少。
- Recall 高：真实方块大多能找到，漏检少。
- F1：综合评价误检和漏检。

还应记录：

```text
平均每帧误检数
完全正确帧比例
连接方块拆分正确率
远距离方块召回率
无方块场景误报率
```

不要只看总体 F1。比赛中如果误抓的代价比漏掉一个方块更高，应优先提高 Precision；如果巡检阶段必须尽量发现所有目标，则应优先提高 Recall。

## 8. 推荐调参顺序

一次只调整一类参数。否则无法知道效果变化来自哪里。

### 8.1 ROI：先排除永远不可能出现方块的区域

配置参数：

```json
"roi_normalized": [x1, y1, x2, y2]
```

范围是图像宽高的 0～1 比例。

例如方块只可能出现在画面下方 80%：

```json
"roi_normalized": [0.0, 0.2, 1.0, 1.0]
```

ROI 可以直接消除墙面、天花板和观众区域误检，但前提是机器人姿态变化时真实方块不会进入被裁区域。

手机视频中的紫色误检有一部分来自墙面和机器人零件，ROI 是第一项应检查的参数。

### 8.2 HSV：让真实方块进入掩膜、背景退出掩膜

使用：

```powershell
python tools\tune_block_detector.py `
  --source "data\test_video.mp4" `
  --config "configs\block_detector_robust.json" `
  --loop
```

调整原则：

1. 先调 H，确定颜色范围。
2. 再提高 S 下限，排除灰白和低饱和背景。
3. 最后调整 V 下限，兼顾暗处方块。

橙色漏检时，检查方块像素的 H 是否低于当前下限；不要直接大幅扩大范围，因为红色场地装饰可能同时进入掩膜。

紫色误检时，优先缩窄 H，并提高 S 下限。观察误检区域是否与真实紫色在 HSV 上确实可分；如果颜色高度重叠，就必须增加形状、位置或尺寸约束。

### 8.3 面积：过滤噪点，但保留最远有效方块

参数：

```json
"min_area_px": 500
```

选择方法：

1. 找到比赛中最远、仍要求识别的真实方块。
2. 记录其轮廓面积。
3. `min_area_px` 设置为该面积的约 50%～70%。
4. 检查小型墙面装饰是否被过滤。

固定像素面积只适用于固定分辨率。分辨率改变后必须重新验证。

### 8.4 形状：排除细长装饰和机器人零件

相关参数：

```text
min_aspect_ratio
max_aspect_ratio
min_rectangularity
min_rotated_rectangularity
min_solidity
min_color_coverage
```

建议顺序：

1. 用宽高比排除特别细长物体。
2. 用旋转矩形度过滤不规则色块。
3. 用实心度过滤凹陷结构。
4. 用颜色覆盖率排除只有少量目标颜色的框。

注意透视下真实立方体可见面不一定是正方形，连接方块轮廓也可能很宽。阈值过严会明显提高漏检。

### 8.5 形态学：最后处理掩膜碎裂和小孔洞

相关参数：

```text
morph_kernel
open_iterations
close_iterations
```

- 开运算减少孤立噪点，但可能吃掉远距离小方块。
- 闭运算填补方块内部空洞，但可能把相邻方块粘连。
- 核越大，影响越强。

连接方块已经有专门分割逻辑，不能依靠无限增大闭运算解决颜色缺口。

## 9. 每次参数修改后的比较流程

1. 复制旧配置并创建新版本，不能直接覆盖唯一基线。
2. 只修改一类参数。
3. 在 `tune` 图片上观察是否改善。
4. 固定参数，不再观看验证集后继续微调。
5. 在 `validation` 图片上统计 TP、FP、FN。
6. 与上一版比较 Precision、Recall、F1。
7. 同时检查典型困难场景，不能只看总分。

推荐记录表：

| 版本 | 修改内容 | Orange P | Orange R | Purple P | Purple R | 无目标误报帧 | 结论 |
|---|---|---:|---:|---:|---:|---:|---|
| v1 | 原始参数 |  |  |  |  |  | 基线 |
| v2 | 收窄紫色H |  |  |  |  |  |  |
| v3 | 增加ROI |  |  |  |  |  |  |

只有验证集改善，才说明参数具有更好的泛化能力。

## 10. 什么时候HSV方案不够用

如果真实紫色方块和机器人零件、墙面装饰具有相似 HSV，同时形状也接近矩形，仅靠调阈值无法同时获得高 Precision 和高 Recall。

此时可以依次增加：

1. 更准确的场地区域 ROI。
2. 基于实际尺寸和透视关系的尺度限制。
3. 地面或平台平面约束。
4. 连续帧运动一致性。
5. 方块底边必须接近可行走/抓取平面的约束。
6. 小型目标检测神经网络。

不要因为传统方法在一段视频上存在上限，就无限扩大或缩小 HSV 阈值。

---

## 11. 手机视频与真实机器人摄像头的关系

手机视频适合：

- 建立代码测试流程
- 找到明显误检类型
- 验证连接方块分割
- 检查运动和透视影响

但手机通常使用自动曝光、自动白平衡、HDR、锐化和视频压缩。手机调出的 HSV 只能作为初值，不能直接视为机器人摄像头最终参数。

真实摄像头到货后应保留相同流程，重新建立：

```text
robot_camera_baseline_v1
```

并在固定曝光、固定白平衡、固定焦距和正式安装视角下重新标注与验证。

---

## 12. 针对当前 test_video.mp4 的建议

根据第一次自动测试和抽帧检查，优先顺序是：

1. 保留无方块但含墙面装饰、机器人结构的负样本。
2. 优先压低紫色误检。
3. 检查橙色 HSV 的 H 下限，解决部分红橙方块漏检。
4. 使用 ROI 排除不可能出现方块的高处区域。
5. 再调整面积和形状阈值。
6. 单独检查连接方块与远距离方块，防止过滤过强。
7. 在固定验证集上比较，而不是只观看完整视频的主观效果。

完成这套流程后，才能客观判断“参数更好”，而不仅是某几个画面看起来更好。
