# 紫色优先与按时间封顶策略

## 材料区

- 紫色方块材料区参考标签：Tag 3。
- 橙色方块材料区参考标签：Tag 4。
- 每次最多携带3个方块，其中紫色最多1个。
- 全场最多按3个可获取紫色方块规划。

树莓派在 `CompetitionCommand.material_tag_id` 中告诉STM32本次应前往的材料区。STM32到达后
回传 `at_material_zone=true` 和实际 `at_material_tag_id`。

## 获取顺序

1. 当前车上没有紫色、紫色尚未判空且累计获取不足3个时，优先前往Tag 3寻找紫色。
2. 紫色装车后，本趟剩余容量只获取橙色，目标切换为Tag 4。
3. 在Tag 3连续 `purple_absence_confirm_s` 没有稳定紫色目标，置位永久的
   `purple_exhausted`，本场后续只去Tag 4获取橙色。
4. 紫色累计获取达到3个后，本场后续也只获取橙色。

“没有紫色”采用稳定目标缺失计时，不是单帧未检出。现场应根据遮挡和相机帧率调整默认3秒。

## 连续平台与虚拟层位

平台没有实体槽。`placement_slots.json` 中的 `building_N_level_M` 是虚拟放置中心：同一建筑
所有层X/Y相同，Z每层增加一个实测方块边长。层位不绑定颜色：橙色表示继续加层，紫色表示
在当前建筑下一层封顶。配置提供3个建筑、每座最多6个层位；未测量或机械臂不可达的层必须
保持 `configured=false`，并相应降低策略最大橙色层数。

## 封顶决策

紫色先保留在车载槽中。只要未达到以下任一条件，优先取出并放置橙色：

- 比赛剩余时间不超过 `roof_when_remaining_s`（默认90秒），且当前建筑至少已有1层橙色；
- 当前建筑达到 `max_orange_layers_before_forced_roof`（默认5层）。

满足条件后优先取出紫色，放到当前建筑的下一层。封顶后该建筑结束，后续方块转移到平台上的
下一建筑锚点。完成3座封顶建筑后停止继续搭建。若紫色已判空，则橙色建筑达到最大安全层数后
转移到下一建筑，不会无限向上堆叠。

90秒和5层都是保守初值，最终必须用抓取、往返、单层放置和封顶耗时的P95实测值调整。
